# Проверка Mini App в Telegram

Используй [инструкцию запуска](../../../integration/telegram-mini-app/README.md). Сначала проверь запущенный Compose-проект и его конфигурацию. Если выделенный `@FinanceBroTestBot` уже работает с `backend/.env`, используй этот стенд и его PostgreSQL. Сверь имя бота через `getMe` перед сменой меню. Для нового изолированного стенда используй `backend/.env.mini-app.test`.

- [ ] Для запуска изолированного стенда выполни `node integration/telegram-mini-app/dev.mjs start` из корня. Оставь процесс работающим на время проверки. Команда проверяет HTTPS и ответ API `401` без авторизации, затем настраивает кнопку тестового бота.
- [ ] Если туннель и кнопка работают, пересобери текущий стенд. Для изолированного стенда используй `node integration/telegram-mini-app/dev.mjs refresh`. HTTPS-адрес остаётся прежним.
- [ ] Открой «Аналитика» в чате тестового бота. Проверь, что приложение загрузилось через меню и показывает операции тестового аккаунта из PostgreSQL. Для нового аккаунта открой «Настройки», чтобы создать стартовые категории, затем добавь тестовую операцию через «История» и сверь сумму с обзором.
- [ ] Проверь затронутый сценарий. Для изменений отображения проверь его в Telegram на мобильном экране. Для изменений интеграции используй подходящий сценарий из инструкции запуска.
- [ ] Зафиксируй результат отдельно для HTTP-проверки и проверки внутри Telegram. Если нет тестовых реквизитов или доступа к клиенту Telegram, выполни доступные проверки и укажи конкретный блокер.

## Восстановление Mini App при пустом экране

1. Проверь локальную главную страницу и `/api/analytics/overview?period=current-month` без авторизации. Ожидаются `200` и `401`. Для Compose с `backend/.env` порт по умолчанию `8081`, для изолированного стенда — `8082`. Прочитай текущий адрес кнопки через `getChatMenuButton` и повтори проверки по HTTPS. Если локальные ответы ожидаемые, а публичный адрес недоступен, восстанови туннель.
2. На macOS проверь существующий launchd-сервис `launchctl print "gui/$(id -u)/local.financebro.mini-app-tunnel"`. Если он ведёт на нужный локальный порт, перезапусти его командой `launchctl kickstart -k "gui/$(id -u)/local.financebro.mini-app-tunnel"`. Возьми новый HTTPS-адрес из свежих строк журнала `cloudflared`. Запись `Unauthorized: Tunnel not found` означает, что старый Quick Tunnel потерял регистрацию. При отсутствии сервиса используй ручной запуск из инструкции и оставь туннель запущенным.
3. Проверь новый HTTPS-адрес до смены кнопки. Если локальный DNS временно отвечает `NXDOMAIN`, сверь ответ публичного резолвера, например `dig @1.1.1.1 <хост> A`. При наличии IP можно проверить HTTP через `curl --resolve '<хост>:443:<IP>'`, сохранив обычную проверку TLS. Для запуска в Telegram дождись, пока адрес начнёт разрешаться в обычном режиме.
4. Обнови кнопку «Аналитика» скриптом `integration/telegram-mini-app/telegram-menu.mjs set` по инструкции запуска. Если Telegram принял `setChatMenuButton`, но `getChatMenuButton` по-прежнему возвращает старый адрес, настрой кнопку через `@BotFather` командой `/setmenubutton`. Выбери тестового бота, введи проверенный HTTPS-адрес и название «Аналитика». Сверь итоговый адрес через `getChatMenuButton`.
5. Закрой Mini App и открой его снова из кнопки. Если Telegram Desktop продолжает открывать закэшированный адрес, перезапусти клиент. Подтверди, что загрузились обзор и данные тестовой базы. При снятии состояния интерфейса исключай из вывода URL-фрагмент с `tgWebAppData` и персональные данные. Токен бота и `initData` в отчёт не включай.
