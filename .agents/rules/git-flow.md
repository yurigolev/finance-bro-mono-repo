# Git Flow в FinanceBro

`main` хранит готовый к выпуску код. `develop` — общая ветка разработки. Обе ветки защищены и принимают изменения через pull request после прохождения обязательного CI.

| Ветка | Откуда создать | Куда открыть PR |
| --- | --- | --- |
| `feature/<описание>` | Из актуальной `develop` | В `develop` |
| `release/<версия>` | Из `develop`, если нужна отдельная стабилизация релиза | В `main` |
| `hotfix/<описание>` | Из актуальной `main` для срочного исправления production | В `main` |

Для имён веток используй короткие слова в нижнем регистре через дефис, например `feature/setup-ci`. Префикс `codex/` запрещён.

Перед созданием ветки обнови ссылки на `origin` и проверь рабочее дерево. В коммит включай только файлы текущей задачи. Публикуй рабочую ветку, открывай PR в указанную целевую ветку и дождись зелёного CI перед merge. После merge проверь итоговый коммит в целевой ветке и статус сборки или деплоя, если они настроены.

Готовый `develop` можно перенести в `main` через PR. При переносе в `main` используй merge commit, чтобы сохранить историю веток. После релиза или hotfix перенеси изменения из `main` обратно в `develop` через PR, если в `develop` их ещё нет. Если для обязательного CI нужна актуальная база, сначала обнови исходную ветку PR целевой веткой.
