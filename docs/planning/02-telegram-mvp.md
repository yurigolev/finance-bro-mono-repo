# FinanceBro — Telegram MVP

Решение от 21 ноября 2026 года. Первый клиент FinanceBro — Telegram-бот. [Веб-клиент](../../web/README.md) переведён в легаси, его разработка приостановлена. Веб-прототип сохранён для локального демо и выведен из плана MVP. [План Swift-прототипа](../../openspec/changes/swift-lock-screen-capture-mvp/proposal.md) поставлен на паузу.

## Цель MVP

Проверить, что короткое сообщение в личном чате позволяет быстро записать доход или расход и что этим способом удобно пользоваться регулярно. Отдельная проверка офлайн-ввода с экрана блокировки возвращается вместе с мобильным клиентом.

Минимальный сценарий:

1. Пользователь отправляет `480 кофе` или `+15000 проект`.
2. Бот определяет тип операции, сумму и описание. При неоднозначном вводе просит уточнить.
3. Бэкенд сохраняет операцию и только после этого бот подтверждает запись.
4. Пользователь может посмотреть последние операции и удалить ошибочную запись.

Первый срез использовал текстовый ввод и RUB. Добавлен голосовой ввод для одного расхода в рублях: локальный `whisper.cpp` с моделью `small`, запись сразу после распознавания и кнопка удаления в чеке. Бюджеты и банковские интеграции отложены.

## Бэкенд

Бэкенд и серверная база ещё не реализованы. В [исходном плане](01-mvp-initial-planning.md#backend) рассматривались PostgreSQL, Supabase и собственный API.

### Стек для MVP

| Слой | Выбор |
| --- | --- |
| Среда и язык | Node.js 24 LTS, TypeScript 7, npm с lockfile. Сборка через `tsc`. |
| Telegram | Telegraf 4.16, long polling через `getUpdates`, один экземпляр бота на токен. |
| База | PostgreSQL 18, драйвер `pg` 8 с пулом подключений. |
| Схема и миграции | Drizzle ORM 0.45, Drizzle Kit 0.31. `drizzle-kit generate` создаёт SQL-файлы, `drizzle-kit migrate` применяет их. SQL-файлы храним в Git. |
| Запуск | Docker Compose с сервисами `bot` и `db`, PostgreSQL в закрытой сети Compose с постоянным томом. Сначала локально, затем при необходимости на Linux VPS. Боту нужен исходящий доступ к Telegram. |
| Конфигурация | `BOT_TOKEN` и `DATABASE_URL` через переменные окружения, примеры без секретов в `.env.example`. |

Node.js 24 уже использовался для веб-демо. PostgreSQL позволяет проверить запись, выборку по владельцу и защиту от дублей на самой БД. Drizzle держит схему в TypeScript и даёт проверяемые SQL-миграции.

### Границы приложения

Один процесс Node.js получает сообщения через Telegraf и вызывает функции учёта. Telegraf переводит сообщение в команду приложения. Логика учёта работает с внутренним ID пользователя и обращается к PostgreSQL через Drizzle. Функции учёта не зависят от контекста Telegraf, поэтому будущий HTTP API сможет вызывать их напрямую. Fastify, публичный домен и входящий HTTPS для этого этапа не нужны.

Минимальная схема состоит из `users` и `transactions`. В `users` храним внутренний ID и уникальную привязку к Telegram ID. В `transactions` храним владельца, тип, сумму в копейках (`bigint`), валюту, описание, дату и ключ идемпотентности на основе Telegram `update_id`. Просмотр и удаление ограничены операциями владельца. Удалённая запись скрывается из списка, а её ключ сохраняется, чтобы повтор обновления не вернул операцию.

### План реализации

1. Создать `backend/`. Настроить TypeScript, npm, переменные окружения и Docker Compose. Добавить схему Drizzle и первую SQL-миграцию. Проверить запуск PostgreSQL с чистого тома.
2. Собрать первый рабочий сценарий. Подключить Telegraf через long polling, принимать сообщения в личном чате. Разбирать `480 кофе`, `+15000 проект` и суммы с копейками. При неоднозначном вводе просить уточнение. Подтверждать запись после сохранения в PostgreSQL.
3. Добавить `/recent` для последних операций и кнопку удаления у записи. Определять владельца по отправителю, в том числе при нажатии кнопки.
4. Проверить парсер, миграции, повторную и конкурентную доставку одного обновления, изоляцию пользователей, ошибку БД и сохранность после перезапуска. Добавить команды запуска в README. Проверить в реальном чате при наличии токена тестового бота.
