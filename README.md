# FinanceBro

Telegram-бот для учёта доходов и расходов в рублях.

[Веб-клиент](web/README.md) переведён в легаси. Разработка приостановлена, прототип сохранён для локального демо. Фокус MVP — Telegram-бот. [Актуальный план](docs/planning/02-telegram-mvp.md).

- Отправьте в личном чате `480 кофе`, `квартира 40 000`, `40к квартира` или `20 000 зарплата`. Если подходят категории только одного типа, бот сразу сохранит доход или расход. При нескольких совпадениях одного типа он предложит подходящие категории в чеке. Если подходят оба типа или совпадений нет, до записи бот предложит выбрать «Доход» или «Расход». Знаки `+` и `-` перед суммой не влияют на тип.
- Для дохода или расхода можно отправить голосовое до 20 секунд и 1 МБ, например «Двести пятьдесят рублей за кофе». После расшифровки действуют те же правила определения типа, категории и даты, что и при текстовом вводе.
- Бот сначала проверяет описание целиком, затем ищет внутри него названия категорий, фразы из словаря и правила. Например, «зарплату дали за проект» предложит «Зарплата» и «Проекты». Стартовые категории можно вводить без эмоджи. Правила личные и разделены по расходам и доходам. Чтобы создать правило для описания, выберите категорию и нажмите «Запомнить» в чеке.
- Отправьте `/start`, чтобы открыть меню под полем ввода. «Статистика» показывает общий доход и расход за сегодня, сводку бюджета за месяц и кнопку перехода к полному бюджету.
- «История» открывает операции и итоги за сегодня. Бот показывает расходы и доходы отдельными списками от новых к старым. Если весь день помещается в сообщение, видны все операции сразу. Кнопки «День» листают даты, «Ещё операции» открывает следующую страницу того же дня, «К сегодня» возвращает к текущей дате. Через «Редактировать операции» можно выбрать запись по сумме и описанию, сменить или снять категорию либо удалить запись с подтверждением. Пока часовой пояс пользователя не задан, границы дня считаются по UTC.
- `/timezone` показывает текущий часовой пояс. Для смены отправьте `/timezone Asia/Yekaterinburg`, для сброса на UTC — `/timezone reset`. История, бюджеты и аналитика рассчитывают границы дня и месяца по выбранному поясу.
- «Бюджеты» (`/budgets`) показывают общий расход и выполнение лимитов по категориям. Установите общий лимит и нужные лимиты по категориям. Суммы действуют каждый месяц до изменения или отключения. Изменения вступают в силу с текущего месяца, а прошлые месяцы доступны для просмотра.
- «Настройки» открывают личный каталог. Выберите «Расходы» или «Доходы», чтобы увидеть стартовые категории, добавить свою, переименовать или архивировать существующую. Для добавления и переименования ответьте на сообщение бота с запросом названия. Архивные категории остаются видны у связанных операций.
- В меню «Настройки» → «Запомненные слова» видны сохранённые правила и их категории. Удаление правила отменяет автоназначение для будущих операций. У уже записанных операций категория сохраняется.
- «Помощь» напоминает формат ввода и назначение кнопок.

## Локальный запуск

Нужен Docker с Compose. Для первого запуска создайте `backend/.env` по образцу `backend/.env.example` и заполните поля.

- `BOT_TOKEN` — токен тестового бота от BotFather.
- `POSTGRES_PASSWORD` — случайный пароль PostgreSQL. Подойдёт значение из `openssl rand -hex 24`.
- `CORE_SERVICE_TOKEN` и `INPUT_SERVICE_TOKEN` — два отдельных случайных секрета, каждый можно получить командой `openssl rand -hex 32`.
- `DATABASE_URL` — `postgresql://financebro:<пароль>@db:5432/financebro`. Подставьте тот же пароль. Специальные символы в пароле кодируйте для URL.

При обновлении существующего `backend/.env` добавьте оба сервисных секрета.

Запускайте Compose из корня проекта.

```sh
docker compose --env-file backend/.env up -d --build
docker compose --env-file backend/.env ps
docker compose --env-file backend/.env logs --tail=50 core bot input whisper
```

Compose поднимает PostgreSQL, применяет SQL-миграции через Drizzle Kit и запускает финансовое ядро, Telegram-бота и обработчик ввода. При обновлении используется существующий том PostgreSQL. Старые суммы, описания и ключи повторной доставки сохраняются. У старых операций категория сначала отображается как «Без категории».

При первом запуске Compose собирает `whisper.cpp` и скачивает многоязычную модель `small` (~466 МиБ) в том `whisper-model`. Дождитесь статуса `healthy` у `whisper`. Он распознаёт русский язык на CPU внутри закрытой сети. По умолчанию используются два потока. Чтобы изменить число потоков, задайте `WHISPER_THREADS` в `backend/.env` и повторите запуск Compose. Бот скачивает голосовые из Telegram и передаёт их обработчику. Обработчик проверяет аудио во временной памяти контейнера и передаёт его Whisper. FinanceBro не сохраняет аудио и полные расшифровки в PostgreSQL.

Бот получает обновления через long polling. На один токен запускайте один процесс. К PostgreSQL подключаются финансовое ядро и миграции. Данные лежат в томе `postgres-data`. Бот вызывает внутренние API ядра и обработчика. Другим доверенным клиентским бэкендам можно выдать отдельные токены через `INPUT_CLIENT_TOKENS` (через запятую) и предоставить доступ к приватному `POST /v1/parse`.

### Запуск с Mini App

```sh
docker compose --env-file backend/.env --profile mini-app up -d --build
```

Nginx раздаёт Mini App на `http://127.0.0.1:8081` и проксирует `/api/` к финансовому ядру. Порт на хосте можно изменить через `MINI_APP_PORT` в `backend/.env`. Для запуска внутри Telegram нужен доступный HTTPS-адрес. См. [инструкцию тестового запуска](integration/telegram-mini-app/README.md).

Внутренние контракты описаны в [OpenAPI обработчика](backend/services/input/input.openapi.yaml) и [OpenAPI ядра](backend/services/core/core.openapi.yaml).

### Проверка голосового ввода

1. Отправьте боту «Двести пятьдесят рублей за кофе» голосовым. Проверьте чек на 250 ₽ и расход в «Истории».
2. Нажмите «Удалить» в чеке. Чек должен показать «Операция удалена», а запись исчезнуть из истории и итогов.
3. Отправьте «Кофе за двести и такси за пятьсот». Бот должен попросить уточнить сумму и описание одной операции.

### Остановка

```sh
docker compose --env-file backend/.env --profile mini-app down
```

Записи сохраняются в томе. Следующий запуск Compose использует тот же том.

## Проверки и миграции

ESLint проверяет TypeScript и шаблоны Vue. Prettier форматирует код бэкенда и Mini App. Команды запускаются из корня проекта на Node.js 24.

```sh
npm ci
npm run lint
npm run format:check
```

`npm run lint:fix` применяет исправления ESLint. `npm run format` форматирует файлы.

В Git-репозитории `npm ci` устанавливает хук Husky. Перед коммитом он запускает `lint` и `format:check`. Ошибка проверки блокирует коммит.

В `backend/services/` лежат три npm-workspace: `core` (финансовое ядро, API и PostgreSQL), `bot` (Telegram и HTTP-клиенты), `input` (разбор операций, ответов о датах и лимитах, вызов Whisper). Каждый собирается в свой образ с кодом и зависимостями сервиса. Общие HTTP-контракты находятся в `backend/packages/contracts/`, календарь и категории — в `backend/packages/shared/`. Бот хранит черновики диалогов, а после разбора передаёт структурированные команды ядру.

Команды разработки запускаются из `backend/` с Node.js 24:

```sh
npm ci
npm run build
npm run typecheck
npm test
npm run db:generate
```

`db:generate` создаёт SQL-миграцию при изменении схемы. SQL и метаданные находятся в `backend/services/core/drizzle/`. Чтобы применить миграции отдельно, из корня проекта запустите `docker compose --env-file backend/.env run --rm migrate`.

Для проверки учёта задайте `DATABASE_URL` отдельной тестовой PostgreSQL и выполните `npm run db:migrate`, затем `npm run test:integration`. Для проверки чистой установки и обновления задайте также `MIGRATION_TEST_DATABASE_URL` выделенного тестового PostgreSQL с правом `CREATEDB`. Тесты миграций создают и удаляют временные базы в этом экземпляре.
