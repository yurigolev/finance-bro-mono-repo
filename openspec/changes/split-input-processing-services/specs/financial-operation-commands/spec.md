# Financial Operation Commands

## Purpose

Позволяет авторизованным клиентским сервисам сохранить разобранную операцию и обновить категорию с проверкой владельца и защитой от дублей.

## ADDED Requirements

### Requirement: Запись структурированной операции

Финансовое API SHALL принимать команду с владельцем, типом, суммой, валютой, описанием, датой или контекстом для её определения, категорией или `null` и ключом идемпотентности. Ядро SHALL проверять корректность полей и доступ вызывающего сервиса к владельцу.

#### Scenario: Категорию выберут после записи

- **WHEN** авторизованный клиент присылает валидный расход с `categoryId: null`
- **THEN** ядро сохраняет расход без категории и возвращает его идентификатор

#### Scenario: Выбрана недоступная категория

- **WHEN** команда содержит архивную, чужую или несовместимую по типу категорию
- **THEN** ядро возвращает ошибку недоступной категории без записи операции

### Requirement: Повтор команды создания

Ядро SHALL обеспечивать уникальность операции по владельцу и ключу идемпотентности. Повтор идентичной команды возвращает идентификатор исходной операции.

#### Scenario: Ответ потерялся после записи

- **WHEN** ядро сохранило операцию, ответ потерялся и клиент повторяет команду с тем же телом и ключом
- **THEN** ядро возвращает тот же идентификатор без создания дубля

#### Scenario: Повтор после удаления

- **WHEN** ранее созданная операция удалена и клиент повторяет исходную команду
- **THEN** ядро распознаёт повтор и не восстанавливает удалённую операцию

### Requirement: Назначение категории сохранённой операции

Ядро SHALL изменять или снимать категорию только у активной операции указанного владельца. Назначаемая категория должна быть активной и относиться к тому же владельцу и типу операции.

#### Scenario: Категорию архивировали во время диалога

- **WHEN** клиент пытается назначить категорию, архивированную после показа кнопок
- **THEN** ядро возвращает `category_unavailable` и оставляет запись без изменений, чтобы клиент мог обновить варианты

#### Scenario: Пользователь выбирает новую категорию

- **WHEN** авторизованный клиент передаёт доступную категорию для сохранённой операции
- **THEN** ядро подтверждает изменение категории той же операции
