# Design

## Context

`backend/src/main.ts` запускает long polling и HTTP API Mini App. Бот получает доменные операции через `TelegramDependencies`, поэтому HTTP-клиент можно подключить с минимальными правками обработчиков. `recordOperation` сейчас сопоставляет правила и записывает результат в одной транзакции. Парсер и состояние уточнений находятся в Telegram-модуле. Whisper и Mini App уже развёртываются отдельно.

Схема контейнеров и последовательность запросов в [Excalidraw](../../../docs/financebro-c4-containers.excalidraw).

## Goals / Non-Goals

**Цели**

- Дать боту и другим клиентским бэкендам единый контракт разбора.
- Сохранить сценарии, данные, Mini App API и поведение Telegram при повторах.
- Разделить транспортную миграцию и перенос логики сопоставления, проверяя их отдельно.

**Границы**

- В рамках change остаются текущие PostgreSQL, Telegram long polling, модель Whisper и репозиторий.
- Интеграция новых клиентских интерфейсов и масштабирование бота на несколько poller'ов выходят за рамки.

## Decisions

### Ответственность контейнеров

| Контейнер | Ответственность |
| --- | --- |
| Telegram-бот | Telegram API, скачивание файла, очередность апдейтов, экраны, callback'и, сессии уточнений. Получает контекст из ядра, вызывает разбор, отправляет команды записи. |
| Обработчик ввода | Принимает текст или аудио и контекст, вызывает Whisper для аудио, разбирает ввод и применяет правила сопоставления. Возвращает JSON. |
| Whisper | Транскрибирует загруженное аудио через существующий `/inference`. |
| Финансовое ядро | Единственный прикладной владелец PostgreSQL. Отдаёт контекст, обслуживает Mini App API, проверяет и выполняет финансовые команды. |
| Mini App | Обращается к публичному API через текущий same-origin прокси, который переключается на ядро. |

Связь синхронная по HTTP. Обработчик получает контекст от вызывающего бэкенда и работает без подключения к Telegram, PostgreSQL и API ядра. Такой вызов подходит для других клиентов и сохраняет синхронный ответ, нужный для диалога. Границы проверяются сетями Compose и набором секретов каждого контейнера. Внешние интеграции идут через авторизованные клиентские бэкенды. Их доступ выдаётся отдельно.

### Контракты HTTP

Зафиксировать запросы и ответы в OpenAPI и валидировать на границе сервиса. Для бота кодировать `bigint` как строку в копейках и восстановить типы при маппинге в домен.

| Вызов | Данные |
| --- | --- |
| Бот → ядро, `GET /internal/v1/users/{telegramUserId}/input-context` | Часовой пояс, активные категории обоих типов и пользовательские правила, включая переопределения. Снимок должен содержать всё, что требуется для действующего приоритета совпадений. |
| Клиент → обработчик, `POST /v1/parse` | `application/json` с `text` и `context` либо `multipart/form-data` с `audio` и JSON-частью `context`. В обоих вариантах контекст включает `sentAt` в ISO 8601 со смещением, IANA `timeZone`, категории и правила. |
| Обработчик → Whisper, `POST /inference` | Аудиофайл. Сохранить текущие модель, формат вызова и обработку расшифровки. |
| Бот → ядро, `POST /internal/v1/operations` | `telegramUserId`, `idempotencyKey`, `kind`, `amountKopecks`, `currency`, `description`, `operationDate` и `categoryId`. Если ввод без явной даты, сохранить существующий способ определения даты. |
| Бот → ядро, `PATCH /internal/v1/operations/{operationId}` | Идентификатор владельца и выбранный `categoryId` или `null` для снятия категории. |

Оба внутренних API аутентифицируют вызывающий сервис. Ядро сопоставляет Telegram ID и внутреннего владельца и проверяет доступ клиента к запрошенному владельцу. Публичный API сохраняет действующую проверку Telegram `initData`. Исходное аудио и расшифровка не передаются в команду записи. Логи по умолчанию содержат идентификаторы запросов и коды ошибок без аудио, расшифровки, правил и секретов.

Для аудио сохранить текущие лимиты бота 20 секунд и 1 МиБ. Обработчик проверяет лимиты и тип аудио на собственной границе для всех клиентов. Различать ошибку запроса, лимит, пустую расшифровку, неразбираемый ввод и сбой Whisper. Отдельные таймауты и тесты нужны для разбора, получения контекста и записи.

### Пример результата разбора

Голосовое от 24.11.2026 в `Asia/Yekaterinburg`. Варианты условны и оба относятся к расходам. Если существующие правила однозначно выводят тип, после подтверждения даты бот показывает чек с вариантами категории. Ветка уточнения типа из диаграммы применяется, когда правила не дают однозначного типа.

```json
{
  "transcript": "В прошлый вторник кофе в путешествии 400р",
  "draft": {
    "kind": "expense",
    "amountKopecks": "40000",
    "currency": "RUB",
    "description": "кофе в путешествии",
    "operationDate": { "date": "2026-11-17", "timeZone": "Asia/Yekaterinburg" }
  },
  "categoryCandidates": [
    { "id": "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa", "kind": "expense", "name": "Кафе" },
    { "id": "bbbbbbbb-bbbb-4bbb-8bbb-bbbbbbbbbbbb", "kind": "expense", "name": "Путешествия" }
  ],
  "needsClarification": ["operationDate", "categoryId"],
  "dateConfirmation": {
    "dates": ["2026-11-17"],
    "today": "2026-11-24",
    "timeZone": "Asia/Yekaterinburg"
  }
}
```

Результат передаёт кандидатов даты для существующего диалога подтверждения. «В прошлый вторник» требует явного подтверждения даже с одним вариантом. Короткая дата может дать несколько вариантов. Часовой пояс и время исходного сообщения фиксируются для этого разбора. Сравнение нового сопоставления с текущим выполняется на одном и том же контексте, включая встроенные слова, точные совпадения, приоритеты фраз, пользовательские переопределения и фильтрацию по типу. Правила для «Запомнить категорию» сохраняются через ядро.

### Повторы и устаревшие данные

- Сохранить текущие форматы ключей Telegram для текста и голоса. Ядро опирается на существующее ограничение уникальности по владельцу и ключу. Повтор того же запроса после таймаута возвращает исходный `operationId`; повтор после удаления не восстанавливает запись. Бот различает восстановление ответа своего запроса и повторную доставку Telegram, для которой сохраняет действующий UX дубля.
- При изменении сохранённой операции ядро проверяет владельца, активность и совместимость категории внутри транзакции. При `409 category_unavailable` бот освежает список и повторно показывает варианты. Ошибки архивации между разбором и первым POST также обрабатываются с повторным выбором, пока записи ещё нет.
- Ядро фиксирует уникальность и результат записи до выдачи успешного ответа. Проверки включают конкурирующие запросы и повтор с тем же ключом после потери ответа.

## Risks / Trade-offs

- Разделение транзакции сопоставления и записи → сравнить решения на совместимых снимках, затем проверить изменившийся каталог при записи.
- Таймаут после коммита → повторить ту же команду с тем же ключом и восстановить идентификатор.
- Переключение poller'а с диалогами в памяти → остановить приём обновлений, дождаться завершения уже принятой работы, оставить один активный poller. Проверить перенос либо действующее поведение истечения сессии при рестарте.
- Частичный откат → сохранить на время переключения совместимый HTTP-адаптер и точку отката раздельно для каждого маршрута.

## Migration Plan

1. Зафиксировать эталон на текущем коде и данных. Добавить проверки для промежуточных состояний и сбоев, где действующих тестов недостаточно.
2. Поднять ядро с текущими функциями и отдельной точкой запуска. Переключить публичный API Mini App на ядро и подтвердить совместимость маршрутов, авторизации и ответов.
3. Провести через совместимый HTTP-адаптер текущий `recordOperation`, затем остальные `TelegramDependencies`. Довести бота до работы без `DATABASE_URL` при прежних экранах и семантике.
4. Вынести парсер, сопоставление и вызов Whisper в обработчик. Прогнать те же примеры через новый контракт без записи и сравнить решения, включая варианты уточнения. Проверить запрос от второго тестового клиента.
5. Переключить бот на результат `/v1/parse`, структурированный POST и PATCH. Включить по одному маршруту, сначала текст, затем голос. На время проверки сохранить предыдущий маршрут для отката и один активный poller.
6. После сквозной проверки закрепить сетевые границы и убрать временный маршрут. Для отката при переключении вернуть бот на предыдущий совместимый маршрут с теми же ключами и PostgreSQL. Откат API Mini App выполняется сменой upstream на предыдущий совместимый процесс. Порядок переключения и отката описан в [инструкции](rollout.md).
