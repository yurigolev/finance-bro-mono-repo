# Переключение и откат

## Порядок миграции

1. Поднять ядро с тем же PostgreSQL и переключить на него same-origin прокси Mini App. Сверить авторизацию и ответы с [эталоном](baseline.md).
2. Подключить бот к совместимому HTTP API ядра. Проверить запись через прежнюю доменную функцию. У бота не должно быть реквизитов PostgreSQL.
3. На переходной сборке включить новый маршрут только для текста (`INPUT_TEXT_ENABLED=true`, `INPUT_VOICE_ENABLED=false`). Завершить работу предыдущего poller'а перед запуском нового. Проверить текст, голос и повтор доставки.
4. Включить новый маршрут для голоса (`INPUT_VOICE_ENABLED=true`). Проверить голосовой запрос до чека, повтор записи после таймаута и смену категории, которую успели архивировать.
5. Проверить обратное переключение на переходной сборке с теми же PostgreSQL и ключами Telegram. После проверки заменить её финальной сборкой с разделёнными контейнерами.

## Откат после перехода

Выбрать согласованные версии образов бота, ядра и прокси из последней успешно проверенной точки. Для переходной версии использовать настройки из шага, к которому выполняется откат. Остановить текущий poller и дать ему завершить уже принятый пакет, затем запустить один poller из выбранной версии. Использовать существующий том PostgreSQL, сохранённые ключи идемпотентности и Telegram-токен. Рестарт обрабатывает незавершённые диалоги по текущим правилам истечения сессии в памяти. После отката сверить сохранённую операцию в истории и убедиться, что повтор того же обновления не создал новую запись.

## Результаты проверки

- В отдельном Compose с тестовым Telegram API выполнили переключение текста, затем голоса и откат. Во всех прогонах максимум один одновременный long poll. Повтор после отката использовал тот же ключ и сохранил одну запись.
- Финальный голосовой сценарий подтвердил дату 17.11.2026 и сумму 400 ₽. После потери ответа на создание повтор вернул ту же операцию. Архивная категория дала 409. Бот обновил варианты и назначил другую категорию исходной операции.
- Второй клиент с отдельным токеном получил тот же структурированный ответ для того же контекста. Для эквивалентного аудио добавилась расшифровка.
- В браузере после переноса Mini App прошли аналитика, история, ручная запись, сравнение, бюджеты и настройки через same-origin прокси. Владелец и срок действия `initData` проверены отдельно.
- Backend — 72/72 теста с FFmpeg и тестовым PostgreSQL, PostgreSQL integration — 36/36. Сборки, typecheck, ESLint и форматирование прошли.
- В финальной конфигурации авторизованный вызов прежней команды записи возвращает 404. Бот не видит PostgreSQL и Whisper, обработчик не видит PostgreSQL, ядро и Telegram.
- При холодном старте Compose дождался готовности ядра и обработчика перед включением poller. Голос, повтор, Mini App и сетевые границы повторно проверены после этого изменения.
