# Design

## Context

Бэкенд связывает Telegram ID с внутренним ID пользователя. Операции содержат дату совершения, категорию, сумму в копейках и отметку удаления. История и бюджеты уже опираются на часовой пояс профиля. Цели и границы релиза описаны в [proposal.md](proposal.md), наблюдаемое поведение — в [спецификации](specs/telegram-mini-app-analytics/spec.md).

## Goals / Non-Goals

- Пользователь видит итог за период без прокрутки и может уточнить сумму за день или долю расходов в категории.
- Одна страница в Mini App, один запрос на период. Бот остаётся точкой ввода и редактирования.
- Настройка темы, отдельная навигация и детализация до операции вынесены за рамки экрана.

## Decisions

### Компоновка первого экрана

**Утверждённые макеты** · [Тёмная тема](mockups/analytics-dark.png) · [Светлая тема](mockups/analytics-light.png)

Оба макета задают одну компоновку для двух тем. По референсу Wallet в Telegram тёмная тема использует графитовые поверхности, светлая — холодный светлый фон. Голубой обозначает доходы, мягкий коралловый — расходы. Суммы, категории и столбцы на макетах иллюстративные. При смене темы сохраняются порядок секций, отступы и выбранный день.

Базовый макет — 390 CSS px, контрольный узкий экран — 320 px. Одна колонка, поля слева и справа по 16 px, между секциями 24 px. Основной скролл вертикальный. Заголовок страницы и первый блок учитывают безопасную область Telegram. Для функций WebView используем проверки поддержки и CSS-отступы устройства как запасной вариант.

| Сверху вниз | Содержание и взаимодействие |
| --- | --- |
| Заголовок «Аналитика» | Один заголовок без дублирования кнопок закрытия Telegram. |
| Период | Сегменты «Этот месяц», «7 дней», «Прошлый месяц». Ниже фактический диапазон, например «1–21 ноября 2026». При UTC по умолчанию рядом показываем «UTC». Минимальная высота области нажатия 44 px. На узком экране подписи могут переноситься. |
| Итоги | «Разница» крупно, например «+34 240 ₽». Ниже в двух колонках «Доходы» и «Расходы», например «72 500 ₽» и «38 260 ₽». Разница может быть отрицательной. Длинные суммы переносятся в две строки или переводят пару метрик в одну колонку. Суммы используют табличные цифры и формат ru-RU. |
| «По дням» | Парные столбцы доходов и расходов с общей нулевой линией, высота около 200 px. Легенда из двух подписей. На оси X видны первый и последний день и до трёх промежуточных дат. Тап выбирает день и показывает точные суммы в строке под графиком. Кнопка «Данные по дням» раскрывает текстовую таблицу с датой и двумя суммами. Строки можно выбрать клавиатурой для подсветки на графике. |
| «Расходы по категориям» | Для каждой категории — название, сумма, доля от всех расходов и полоса с длиной по доле. Сортировка по сумме, при равенстве по названию и ID. «Без категории» участвует в общей сортировке. Длинные названия переносятся. Значения долей округляются только при отображении. |

При первом открытии и смене периода структура экрана сохраняется, значения заменяются скелетонами. Даты, суммы и серии обновляются вместе. Ответ для предыдущего выбора отбрасывается. Пустой период показывает нули и сообщение «За этот период операций нет». При наличии только доходов вместо списка категорий появляется «За этот период расходов нет». При сбое показываем «Не удалось загрузить аналитику» и кнопку «Повторить». Вне Telegram или при истёкших данных запуска показываем «Откройте аналитику из меню бота». При возврате к активному Mini App обновляем выбранный период, чтобы учесть запись через бот.

### Тема и компоненты

Кастомный интерфейс на shadcn-vue и Reka UI. Reka отвечает за доступное управление сегментами и раскрывающимся списком, shadcn-vue — за редактируемые компоненты. Переменные Telegram подставляются в токены поверхностей, текста и акцента, с нейтральными светлыми и тёмными значениями по умолчанию. Серии графика используют контрастные цвета для обеих тем, подписи и постоянный порядок столбцов. Смена темы и изменение размера WebView не сбрасывают период. Учитываем настройку уменьшенного движения. [Reka UI](https://reka-ui.com/docs/overview/introduction) · [Темы и WebView Telegram](https://core.telegram.org/bots/webapps#initializing-mini-apps)

Для графика выбираем Unovis через shadcn-vue Chart. Он даёт парные столбцы, оси и подсказку с локальными цветами. Для категорий достаточно полос на CSS с текстовыми суммами. Apache ECharts с Vue ECharts остаётся вариантом для будущих интерактивных графиков со сложной навигацией. На реальных устройствах проверяем размер клиентской сборки, читаемость месяца и конфликт тапа с вертикальным скроллом. [shadcn-vue Chart](https://www.shadcn-vue.com/docs/components/chart) · [Vue ECharts](https://github.com/ecomfe/vue-echarts)

### Клиент, API и расчёты

- Отдельное приложение в `mini-app/` на Nuxt 4, Vue 3 и TypeScript. Клиентский рендеринг и статическая сборка сокращают число серверных процессов. HTTPS-прокси отдаёт сборку и маршрутизирует `/api/` в существующий бэкенд на том же origin. [Режимы размещения Nuxt](https://nuxt.com/docs/4.x/getting-started/deployment)
- `GET /api/analytics/overview?period=current-month|last-7-days|previous-month`. Проект ответа включает начало и конец периода в локальных датах включительно, применённую зону и признак UTC по умолчанию, валюту, число операций, итоги, дневные ряды и категории расходов. Точные суммы в копейках передаём десятичными строками, округление применяем только при выводе. Некорректный период возвращает `400`, отсутствующий либо недействительный запуск — `401`.
- Исходный `initData` отправляем заголовком запроса. Сервер проверяет его подпись по правилам Telegram и свежесть `auth_date`, затем по подтверждённому Telegram ID разрешает внутренний ID владельца. Токен бота хранится на сервере. Заголовки с данными запуска и ответы с финансовыми данными исключаем из логов, ответы помечаем `Cache-Control: no-store`. [Проверка данных запуска](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app)
- Источник — существующие операции PostgreSQL. Бэкенд агрегирует данные по владельцу, используя `occurred_at`, часовой пояс профиля с запасным UTC и фильтр `deleted_at IS NULL`. Суммы по дням и категориям формируются из одного согласованного снимка. Дни без записей дополняются нулями. Архивные категории сохраняют название, отсутствующая категория группируется отдельно.

## Risks / Trade-offs

- Разный день у бота и Mini App → единая политика часового пояса, тесты на границе суток, смену месяца и переходы летнего времени.
- При серии запросов ответы могут прийти в обратном порядке → принимать результат только для последнего запроса.
- Истёкший запуск при открытом WebView → показать запрос на повторное открытие. Порог свежести задаётся на сервере.
- На узком дисплее график за месяц плотный → разреженные подписи, значения выбранного дня и текстовая таблица.

## Migration Plan

Сначала разместить фронт и API под HTTPS и включить кнопку на тестовом боте. Проверить реальные iOS и Android, данные двух пользователей и сверку с ботом. Затем включить кнопку на основном боте. Для отката убрать ссылку из меню и отключить маршрут Mini App. Данные операций остаются в существующей схеме.
