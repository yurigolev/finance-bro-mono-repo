# Telegram Mini App Analytics

## Purpose

Пользователь может открыть в Telegram личный обзор операций, ранее записанных через FinanceBro, и оценить доходы, расходы и структуру трат за выбранный период.

## ADDED Requirements

### Requirement: Доступ к личной аналитике через Telegram

Бот SHALL предоставлять кнопку «Аналитика» в меню личного чата. Сервис SHALL выдавать аналитику только владельцу, определённому по проверенным данным запуска Telegram.

#### Scenario: Запуск из личного чата

- **WHEN** пользователь открывает Mini App через меню бота и передаёт действительные данные запуска
- **THEN** Mini App показывает обзор только его собственных операций
- **AND** дополнительный вход не требуется

#### Scenario: Недействительные данные запуска

- **WHEN** данные запуска отсутствуют, подменены или просрочены
- **THEN** сервис отклоняет запрос без выдачи финансовых данных
- **AND** экран предлагает открыть аналитику из бота заново

### Requirement: Итоги за выбранный период

Экран SHALL показывать доходы, расходы и их разницу в рублях за выбранный период. Доступны «Этот месяц», «7 дней» и «Прошлый месяц». Значение по умолчанию — «Этот месяц».

#### Scenario: Семь календарных дней

- **WHEN** пользователь выбирает «7 дней»
- **THEN** обзор включает сегодня и шесть предыдущих календарных дней в часовом поясе пользователя
- **AND** экран показывает фактические даты периода

#### Scenario: Границы месяца

- **WHEN** пользователь открывает обзор текущего или прошлого месяца
- **THEN** текущий месяц охватывает дни с первого числа по сегодня, прошлый месяц — все его дни
- **AND** границы рассчитываются по часовому поясу, используемому ботом, с UTC при отсутствии настройки
- **AND** удалённые записи исключаются, а остальные учитываются по дате операции

### Requirement: Динамика доходов и расходов по дням

Экран SHALL показывать отдельные ряды доходов и расходов по дням выбранного периода. Значения для дня SHALL быть доступны касанием и с клавиатуры и иметь текстовое представление.

#### Scenario: Просмотр значений дня

- **WHEN** пользователь выбирает день на графике или в текстовой сводке
- **THEN** экран показывает дату и обе суммы этого дня
- **AND** день без операций имеет нулевые значения в обоих рядах

### Requirement: Структура расходов

Экран SHALL показывать сумму и долю расходов по каждой категории за выбранный период. Доли вычисляются от всех расходов периода, категории сортируются по убыванию суммы.

#### Scenario: Операция без категории или с архивной категорией

- **WHEN** в периоде есть расходы без категории или с архивной категорией
- **THEN** расходы без категории отображаются единой строкой «Без категории»
- **AND** архивная категория отображается под сохранённым названием
- **AND** обе суммы входят в общий итог

### Requirement: Состояния первого экрана

Экран SHALL отображать загружаемый, пустой, успешный и ошибочный результат выбранного периода. Суммы одного периода SHALL отображаться только вместе с его датами.

#### Scenario: Не было расходов

- **WHEN** в периоде есть доходы, но отсутствуют расходы
- **THEN** экран показывает итоги и динамику доходов
- **AND** блок категорий показывает «За этот период расходов нет»

#### Scenario: Период без операций

- **WHEN** в выбранном периоде нет операций
- **THEN** экран показывает нулевые итоги и сообщение «За этот период операций нет»
- **AND** выбор другого периода остаётся доступен

#### Scenario: Ошибка загрузки

- **WHEN** загрузка действительного запроса завершается сетевой или серверной ошибкой
- **THEN** экран показывает сообщение об ошибке и действие «Повторить» для выбранного периода
