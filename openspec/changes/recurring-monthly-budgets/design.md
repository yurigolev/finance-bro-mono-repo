# Design

## Context

Операции уже хранят сумму в копейках, `occurred_at`, категорию и отметку удаления. Дневная история использует часовой пояс пользователя с переходом на UTC при отсутствии настройки. Категории привязаны к владельцу и типу операции. Архивирование сохраняет запись категории.

## Goals / Non-Goals

**Goals** — использовать текущую модель операций и доступа, сохранять историю лимитов, рассчитывать актуальный факт одним запросом к расходам за месяц.

**Non-Goals** — отдельный отчётный сервис, фоновые задачи смены месяца и автоматические уведомления.

## Decisions

### Хранение лимитов

Добавить `budget_limit_versions` с полями `user_id`, `category_id`, `kind`, `effective_month` и `amount_kopecks`. Пустой `category_id` задаёт общий лимит. `kind` фиксирован на `expense`, а составной внешний ключ на `(user_id, kind, category_id)` обеспечивает принадлежность категорийного лимита владельцу и типу. `effective_month` хранится как `date` первого числа месяца. Положительная сумма в копейках задаёт лимит, `NULL` явно отключает его с указанного месяца.

Уникальность обеспечить двумя частичными индексами: `(user_id, effective_month)` для общего лимита и `(user_id, category_id, effective_month)` для категорийного. Сохранение работает атомарным upsert по области и месяцу. Категорию при записи проверить под блокировкой строки, совместимой с текущим архивированием. Для просмотра брать последнюю версию каждой области с `effective_month` не позже выбранного месяца, включая отключения. Одна перезаписываемая настройка теряла бы историю, а копирование лимитов в каждый месяц потребовало бы создавать лишние записи.

### Расчёт исполнения

Использовать `getTimeZone` и существующий fallback на UTC. Границы выбранного месяца — от первого числа включительно до первого числа следующего месяца исключительно по местной дате. Как и в дневной истории, ограничить индексное сканирование `occurred_at` расширенным диапазоном UTC, затем применить точный фильтр по местной дате. Это учитывает обе версии повторяющейся местной полуночи. Сгруппировать расходы владельца по `category_id`, включая `NULL`. Сумма всех групп даёт общий факт. Отсутствующая группа означает ноль. Сохранять точность копеек в SQL и TypeScript.

Видимость лимита архивной категории определяется местным месяцем `archived_at`. Строка доступна до этого месяца включительно. Смена имени категории отображается по текущему имени при сохранении привязки по идентификатору. Расчёт при чтении учитывает исправления операций и обходится без синхронизации отдельных счётчиков.

### Telegram

Переиспользовать меню, навигацию в одном сообщении и обработку ввода с отменой. Кнопки редактирования доступны в текущем месяце. Привязать действия к владельцу и месяцу экрана. Если месяц сменился во время ввода, предложить открыть актуальный экран, чтобы сумма не вступила в силу неожиданно. Использовать существующий формат рублей и правила разбора суммы. При большом числе лимитов разбивать список на страницы в рамках одного сообщения, сохраняя общий факт на каждой странице.

## Risks / Trade-offs

- Границы месяца в зонах со сменой смещения → вычислять начало и конец отдельно, проверять сценарии с переходом через местную полночь и сменой смещения.
- Исторические итоги меняются при исправлении операций → экран показывает текущие данные по прошлому периоду. Историческое значение лимита сохраняется отдельно.

## Migration Plan

Применить добавочную миграцию перед запуском новой версии бота. Таблица начинается пустой, существующие данные остаются доступны для расчёта. При откате к прежнему боту сохранить таблицу для повторного выката.
